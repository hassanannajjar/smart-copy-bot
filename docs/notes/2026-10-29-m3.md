# M3: Paper executor + PositionManager (branch `m3-paper`)

Every PASSED decision now becomes a paper position. Fills come from a fresh Jupiter quote for **our** $50 after the simulated latency, plus real fees. The guard (stop, TP ladder, trailing stop, time stop, rug exit) manages the position until it closes with a full PnL breakdown. This is PAPER only: nothing signs or sends a transaction. The engine was **not** started from this worktree, and nothing was merged.

## What changed
- **`packages/shared/src/providers/jupiter.ts`** (new): `JupiterApi.quote()` calls Swap V2 `/order` **without `taker`**, so it is a quote only. `JupiterApi.prices()` calls Price V3, up to 50 ids. The optional `x-api-key` comes from `JUPITER_API_KEY`. See `docs/providers/jupiter.md`.
- **`helius.ts`**: adds `priorityFeeEstimate()` (`getPriorityFeeEstimate`), additive only. See `docs/providers/helius.md` § M3.
- **`apps/engine/src/paper/guard.ts`** (pure): the initial guard from `rules.yaml`, `evaluate()` (one poll returns a trigger), `sellAmount()` and `pnl()`.
- **`apps/engine/src/paper/executor.ts`**: `startPaper()` exposes `submit(signalId)` (entry), `tick()` (one PositionManager poll) and `start/stop/idle`.
- **`rules/stage.ts`**: one optional hook, `onPassed(id)`, called after a PASSED decision is committed.
- **`boot.ts`**: `readKillSwitch(control)` returns *on* when control.db can't be read, so it fails closed.
- **`main.ts`**: one additive block. It creates the paper executor (Jupiter plus a Helius fee client) and wires rules `onPassed` to `paper.submit`. `paper.start()` runs after the scout. control.db now stays open for live kill-switch reads, and the shutdown order is scout → rules → paper → DBs.
- **Config**: a new top-level **`executor:`** block at the end of `rules.yaml` and `config.ts`. It is additive, and no existing key changed. `paper:`, `guard:` and `prefilters.mint_cooldown_h` are reused as they are.
- **Env**: `JUPITER_API_KEY` is optional (`env.ts`, `.env.example`).
- **No schema change and no migration.** The positions, fills and events_log tables already had every column. The guard state lives in `positions.tp_plan_json`.

## Decisions
| Topic | Decision | Why |
|---|---|---|
| Quote API | Swap V2 `/swap/v2/order` without `taker` | V1 `/quote` is "no longer actively maintained". Without `taker` there's no transaction, so the client can't even build a signable swap. |
| Price polling | Price V3, batched by `executor.price_batch_size` (49 + wSOL), one tick every `paper.poll_interval_s` | One call covers every open position and also returns `liquidity`, which the rug check uses. |
| Mint missing from Price V3 | Mark from a sell quote for our remaining size, and skip the rug check for that poll | Price V3 silently omits unreliable mints. An executable quote is the honest mark. |
| Rate limits | One Jupiter client and **one serial chain** for entries and polls. A slow tick swallows the next one. 2100 ms keyless, 1100 ms with a key. | Jupiter is a single per-org bucket, and `createHttp`'s throttle isn't concurrency-safe. |
| Entry timing | Wait until `detected_at + simulated_latency_ms` (never earlier than now), then quote | Same `detected_at` as the rules stage: `min(block_time, detected_at)`. |
| Exit price | After a trigger: wait the latency, then take a **fresh sell quote for our qty**. Never the stop or trigger price. | Gaps are real. A test shows a stop fill well below `stop_price`. |
| Exit priority | rug > stop_loss > time_stop > take_profit (partial) > trailing_stop | The trailing stop runs only once the TP ladder is done, starting from the mark that completed it. |
| No route | No route on an exit (or no Price V3 entry and no route at all) for `no_route_max_polls` (3) polls in a row: book the rest at 0, `exit_reason='no_route'` | Network errors, 5xx and 429 never count. They are retried next poll. |
| Fees | base_fee_sol + Helius estimate (route ammKeys, `High`) × `compute_units`. If Helius fails, the static `paper.priority_fee_sol`. Platform fee = `feeBps` × notional. | Without a taker, Jupiter's own fee fields are 0. The recorded High estimate is about 0.000035 SOL. The fallback, 0.001, is the conservative one. |
| PnL | gross = proceeds − size + platform fees. `fees_usd` = network + platform. net = gross − fees. `slippage_bps` = signed slippage$ / size × 1e4. | Buy slippage is measured against the decision snapshot price and sell slippage against the trigger mark, so both include latency and impact. |
| `mint_cooldown_h` | Enforced at entry, from the last position's `entry_at` on that mint. It shows as `paper skipped mint_cooldown`. | M2 rules stay untouched. The funnel shows PASSED plus the skip event. |
| Stale PASSED | Skipped when older than `executor.max_entry_delay_s` (60 s) | This covers the boot backlog: no entries on hours-old buys. |
| Kill switch | Read from control.db on every entry, before and after the latency waits. Unreadable means on. It blocks entries only, and open positions keep being managed. | The dashboard toggles it live. Previously the engine read it only at boot. |
| Resume | No in-memory state. Each tick reads the open positions and their guard state from the DB, and boot writes a `resumed` event. | A fill and its guard-state update are one transaction, so a crash can't re-sell a TP level. |
| Decimals | From the PASSED snapshot's RugCheck report | R6 needs RugCheck, so every PASSED decision has the report. |

events_log rows with `stage='paper'`: `opened`, `skipped` (reason: `kill_switch`, `position_open`, `mint_cooldown`, `stale`, `data_unavailable`, `no_route`), `exit` (per fill, with `partial`), `closed` (with the breakdown), `resumed`, `entry_failed` and `manage_failed`. A price-poll outage is logged only, so it doesn't write a row every 5 s. Every log line carries `signal_id`, and positions also carry `position_id`.

## Known ceilings
- ATA rent (~0.002 SOL) is ignored, because it's refunded when the account is closed after the final sell. Gasless RFQ (`jupiterz`) routes are still charged the base fee, which is conservative.
- The rug check needs Price V3 liquidity. It is skipped while a mint is absent from Price V3, though the quote-based mark still catches the crash through the stop.
- The no-route response for a *valid* mint is undocumented, so `order-noroute.json` is doc-derived. Re-record it when one is seen live.
- Placeholders to tune: `max_entry_delay_s`, `no_route_max_polls`, `compute_units`, `rug_liquidity_drop_pct`.

## Rebase, merge, restart
Run steps 1–2 in the **worktree** (`/Volumes/Transcend/mobileApps/smart-copy-bot-m3`) and steps 3–6 in the **main repo**.

1. Rebase onto the latest main (the scout/discovery session's work):
   ```sh
   git switch m3-paper
   git rebase main
   ```
   Likely conflicts and how to resolve them:
   - `config/rules.yaml` / `packages/shared/src/config.ts`: if both sides appended a block at the end, keep **both** blocks.
   - `apps/engine/src/main.ts`: keep main's scout changes, then re-apply the M3 parts:
     - the `createJupiterApi` import, `readKillSwitch` and `startPaper`
     - the paper block before `startRules`, and `onPassed` on it
     - **no** `control.$client.close()` after boot
     - `paper.start()` after the scout
     - `paper.stop()/idle()` and `control.$client.close()` in shutdown
   - `apps/engine/test/fakes.ts`: keep both sides' additions.

   Then run `git add …` and `git rebase --continue`.
2. `pnpm i && pnpm build && pnpm test -- --reporter=dot 2>&1 | tail -60 && pnpm lint`. All of it must pass.
3. Stop the running engine with Ctrl-C (SIGTERM), so it shuts down cleanly. There are no open positions yet, so nothing is lost.
4. Merge: `git switch main && git merge --ff-only m3-paper`.
5. Add `JUPITER_API_KEY=…` to the main repo's `.env`. It is optional, since keyless works at 0.5 rps.
6. Run `pnpm i && pnpm build`, then `pnpm start` from the repo root. No `db:migrate` is needed, because there is no schema change.

## What to check manually after the restart
- The boot log line `engine booted, scout, rules and paper started` shows `openPositions` and `jupiterKey: true`.
- `sqlite3 data/paper.db "select at, message, data_json from events_log where stage='paper' order by id desc limit 20"`: first `resumed`, then `opened` and `skipped` as PASSED signals arrive.
- After the first PASSED signal:
  ```sql
  select id, mint, size_usd, entry_price, stop_price, status from positions;
  select * from fills;
  ```
  Expect `size_usd` ≈ 50, `simulated=1` and `tx_sig` NULL.
- Within 24 h (the time stop), positions close with `gross_pnl_usd, fees_usd, slippage_bps, net_pnl_usd, net_pnl_pct` filled in.
- Check that `priority_fee_source` in the `opened` rows is `helius`. If it shows `static`, look for `priority fee estimate failed` in the logs.
- Watch for `provider 429` lines from `jupiter`. If they show up, raise `executor.jupiter.keyed_min_interval_ms`.
- Kill switch: engage it in the dashboard. The next PASSED signal should log `skipped kill_switch`, while open positions keep being polled.
